# Benchmark results: with and without Lightpath, shop and tududi, 2026-11-03

**Lightpath did not raise the fix rate on either suite, and it cost more.** Without Lightpath, the agent fixed every visible bug in both suites. With Lightpath it did the same, apart from one shop slot that the void rule counts against it (see "A flaw in the void check"). On the held-out bugs, the shop was 9 of 9 in both conditions. On tududi's held-out bugs, `with` did worse: 6 of 10 against 9 of 10, or 7 of 10 if the void check's false hits are set aside. In every set, the `with` runs used more steps, more tokens and more credits.

**Read the tududi numbers with these limits.**

- **All 5 tududi fixes are public** (commits, pull requests and issues on GitHub), so the model may have seen them in training: r01 [#1938](https://github.com/chrisvel/tududi/pull/1938), r02 [#1915](https://github.com/chrisvel/tududi/pull/1915), r03 [#1865](https://github.com/chrisvel/tududi/pull/1865), held-out h01 [#1921](https://github.com/chrisvel/tududi/pull/1921) and h02 [#1898](https://github.com/chrisvel/tududi/pull/1898). ## A flaw in the void check, logged and not fixed

`SCORING.md` voids a run whose tool calls name a path outside the trial folder. That check is conservative, and it fired 5 times on paths that were inside the folder or weren't paths:

| Run                                | What it flagged                                    | What it really was                                        |
| ---------------------------------- | -------------------------------------------------- | --------------------------------------------------------- |
| b06-with-2, b06-with-4 (its rerun) | `/c:/Users/.../b06-with-2/server/routes/orders.ts` | a file inside the trial, written as a `/c:/` URL path     |
| h02-without-3 (tududi held-out)    | `../utils`, `../../utils`                          | the text `require('../utils/...')` inside an edit command |
| h02-with-2, h02-with-6 (its rerun) | `../../utils/attachment-utils`                     | the same: `require(...)` text inside an edit command      |

By the rules as written, a void run is rerun once, and a rerun that is void again counts as not correct. So b06 run 2 (shop `with`) and h02 run 2 (tududi held-out `with`) count as not correct. h02-without-3's rerun was valid. Every flagged run's hidden check passed. Both numbers are given: the rules' number first, the number without the false hits in brackets. The check and the rules aren't changed (D-108). A fix would be Tier 2 and needs its own D-entry.
