- **Run 1: the app never opened.** With `--url`, Lightpath 0.0.2 opens the page as soon as it spawns the dev command (`packages/cli/src/dev.ts`, `if (options.url) void openBrowser(options.url)`), before Vite is up. It logged `page.goto: net::ERR_CONNECTION_REFUSED at http://localhost:3310/` and doesn't retry. This is a Lightpath limit, found here, not fixed by this item. From run 2 the URL is detected from the dev command's output instead.
- **Run 2: the agent had no Lightpath tools.** kiro-cli 2.37 didn't start the MCP server from the clone's agent config (the session's tool breakdown shows 0 MCP tokens). The cause is the workspace trust prompt: kiro-cli's `--trust-workspace` help says a folder's agents and MCP servers load without asking only with that flag. The same `npx ... lightpath mcp` command answered an MCP `initialize` by hand in 3.3 s. The agent answered that it had no file tools and suggested a `Select-String` search. From run 3, `run.mjs` passes `--trust-workspace` and `--require-mcp-startup`.
